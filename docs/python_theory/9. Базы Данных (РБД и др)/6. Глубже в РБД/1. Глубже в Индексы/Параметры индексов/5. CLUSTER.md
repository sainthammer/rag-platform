
Параметр **`CLUSTER`** в SQL (в частности, в PostgreSQL) используется для физической перестройки таблицы на основании определённого индекса. Это приводит к тому, что данные в таблице будут **храниться на диске в порядке**, соответствующем значениям индекса. `CLUSTER` полезен для ускорения запросов, которые часто работают с диапазонами данных, так как данные будут физически упорядочены, что может сократить количество операций ввода-вывода при чтении.

### Как работает `CLUSTER`:

Когда вы используете команду `CLUSTER`, PostgreSQL физически перестраивает таблицу, изменяя порядок строк в соответствии с указанным индексом. Этот процесс выполняется один раз, и в дальнейшем PostgreSQL **не поддерживает** таблицу в таком упорядоченном виде автоматически. Если после этого происходит много вставок, обновлений или удалений, таблица может со временем перестать соответствовать порядку индекса, и для восстановления нужно будет снова выполнить `CLUSTER`.

#### Пример использования:

Предположим, у вас есть таблица `orders`, и вы часто выполняете запросы, которые фильтруют данные по дате заказа (`order_date`). Вы можете кластеризовать таблицу по индексу на колонке `order_date`:

```SQL

CLUSTER orders USING idx_orders_order_date;

```

В этом примере таблица `orders` будет физически перестроена так, чтобы строки хранились на диске в порядке, соответствующем индексу `idx_orders_order_date`.

### Преимущества использования `CLUSTER`:

1. **Ускорение запросов с диапазонами**: Запросы, которые фильтруют или сортируют данные по колонке, участвующей в кластеризованном индексе, могут выполняться быстрее, так как данные будут физически упорядочены на диске. Например, запросы по диапазону дат (`WHERE order_date BETWEEN ...`) могут выигрывать от кластеризации по дате.
    
2. **Меньше операций ввода-вывода**: Благодаря тому, что данные физически упорядочены, последовательное чтение диапазона данных может быть выполнено с минимальным количеством дисковых операций, так как нужные строки будут храниться рядом друг с другом.
    

### Когда использовать `CLUSTER`:

- **Запросы с диапазонами**: Если ваши запросы часто используют диапазоны значений (например, даты, числовые идентификаторы), кластеризация таблицы по соответствующему индексу может значительно повысить производительность.
- **Редкие изменения данных**: Поскольку `CLUSTER` не поддерживает данные в упорядоченном виде после каждой вставки или обновления, это полезно для таблиц, где изменения происходят нечасто или периодически.

### Недостатки и ограничения:

1. **Не автоматически поддерживается**: После выполнения команды `CLUSTER` таблица перестраивается, но новые данные не будут автоматически упорядочены. Для поддержания порядка необходимо периодически повторять команду `CLUSTER`, особенно если таблица активно обновляется или пополняется новыми данными.
    
2. **Затраты на перестроение таблицы**: Команда `CLUSTER` требует ресурсов, так как таблица физически перестраивается. Этот процесс может занять значительное время, особенно для больших таблиц, и во время выполнения команда блокирует таблицу для операций записи.
    
3. **Использование дискового пространства**: Во время выполнения `CLUSTER` база данных создает временные копии таблиц, что требует дополнительного дискового пространства.
    
4. **Не рекомендуется для активно изменяющихся таблиц**: Если таблица часто обновляется или вставляются новые данные, эффекты от `CLUSTER` могут быстро исчезнуть, так как новый порядок нарушается при добавлении данных.
    

### Автоматическая оптимизация:

PostgreSQL не поддерживает автоматическую повторную кластеризацию таблицы, но можно настроить задачи на уровне планировщика (например, через `cron`), чтобы периодически выполнять кластеризацию для таблиц, которые выигрывают от этого.

### Пример автоматической кластеризации:

Чтобы автоматически поддерживать кластеризацию, можно настроить периодическое выполнение команды:

```SQL

VACUUM FULL ANALYZE;
CLUSTER orders USING idx_orders_order_date;

```

Это гарантирует, что таблица будет физически упорядочена в соответствии с индексом через определённые интервалы времени, например, ночью или в моменты низкой активности.

### Альтернативы:

- **Покрывающие индексы (INCLUDE)**: Если целью является только ускорение выборки данных, иногда лучше использовать покрывающие индексы с параметром `INCLUDE`, что может устранить необходимость в кластеризации.
- **Создание кластеризованных индексов** (в других СУБД, например, SQL Server): В некоторых базах данных, таких как SQL Server, можно создавать **кластеризованные индексы**, которые автоматически поддерживают порядок данных в таблице. В PostgreSQL же кластеризация — это разовая операция, которую нужно повторять вручную.

### Заключение:

Параметр **`CLUSTER`** в SQL, особенно в PostgreSQL, используется для физической перестройки таблицы на основании индекса. Это позволяет упорядочить данные на диске и ускорить запросы, которые фильтруют или сортируют данные по этому индексу. Однако кластеризация — это разовая операция, и со временем упорядоченность данных может нарушаться, что требует повторной кластеризации. Она полезна для больших таблиц, которые редко изменяются и где важна производительность запросов по диапазонам значений.
