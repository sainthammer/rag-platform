
Индексы в SQL базах данных могут иметь различные параметры, которые зависят от используемой СУБД (например, PostgreSQL, MySQL, SQL Server). Вот некоторые из наиболее распространенных параметров индексов:

# Кратко про каждый
### 0. **`FILLFACTOR`**

- Параметр **`fillfactor`** в индексе SQL баз данных управляет тем, насколько плотно данные будут заполнять страницы (блоки) индекса при его создании или перестроении. Он определяет процент заполнения страницы индексом, оставляя место для будущих вставок и обновлений данных, тем самым снижая вероятность фрагментации.
- Пример (PostgreSQL):

```sql

CREATE INDEX idx_orders ON orders (order_date) WITH (fillfactor = 70);

```

### 1. **`UNIQUE`**

- Указывает, что индекс должен обеспечивать уникальность значений в колонках, по которым он создается. То есть, в таблице не может быть двух строк с одинаковыми значениями для данных колонок.
- Пример (PostgreSQL/MySQL):

```sql

CREATE UNIQUE INDEX idx_unique_username ON users (username);

```

### 2. **`CONCURRENTLY` (PostgreSQL)**

- Создание или перестроение индекса одновременно с возможностью чтения и записи в таблицу. Это уменьшает время блокировки таблицы при создании индекса, но может занять больше времени.
- Пример:

```sql

CREATE INDEX CONCURRENTLY idx_users_email ON users (email);

```

### 3. **`WHERE` (Partial Index / Частичные индексы)**

- Позволяет создать индекс, который охватывает только часть данных таблицы, соответствующую определённым условиям.
- Пример (PostgreSQL):

```sql

CREATE INDEX idx_active_users ON users (email) WHERE active = true;

```

- Это может улучшить производительность и уменьшить размер индекса, если только определённые строки важны для запросов.

### 4. **`INCLUDE` (PostgreSQL, SQL Server)**

- Добавляет дополнительные колонки в индекс только для хранения (они не участвуют в сортировке индекса), что может ускорить запросы при использовании только этих колонок.
- Пример (PostgreSQL):

```sql

CREATE INDEX idx_orders_customer ON orders (customer_id) INCLUDE (order_date);

```

### 5. **`CLUSTER` (PostgreSQL)**

- Определяет, что данные таблицы должны быть физически отсортированы в соответствии с индексом. Операция требует выполнения команды `CLUSTER` для реорганизации таблицы.
- Пример:

```sql

CLUSTER orders USING idx_orders_date;

```

### 6. **`ASC` / `DESC` (Ascending/Descending Order)**

- Указывает порядок сортировки значений в индексе — по возрастанию или по убыванию. Это может быть полезно для оптимизации запросов с сортировкой.
- Пример:

```sql

CREATE INDEX idx_price_desc ON products (price DESC);

```

### 7. **`WITH (PAD_INDEX, STATISTICS_NORECOMPUTE, SORT_IN_TEMPDB)` (SQL Server)**

- Это параметры, специфичные для SQL Server, которые позволяют более тонко настраивать индексы:
    - **`PAD_INDEX`**: Определяет, нужно ли резервировать место в промежуточных узлах индекса.
    - **`STATISTICS_NORECOMPUTE`**: Отключает автоматическую перестройку статистики для данного индекса.
    - **`SORT_IN_TEMPDB`**: Определяет, использовать ли временную базу данных `tempdb` для сортировки данных при создании индекса, что может уменьшить использование дискового пространства.

### 8. **`USING` (PostgreSQL)**

- Указывает тип индекса, который будет использоваться: B-tree, Hash, GIN, GiST и другие.
- Пример:

```sql

CREATE INDEX idx_users_gin ON users USING GIN (email);

```

### 9. **`ONLINE` (SQL Server)**

- В SQL Server можно создавать и перестраивать индексы "онлайн", т.е. без блокировки таблицы для операций чтения и записи.
- Пример:

```sql

CREATE INDEX idx_email ON users (email) WITH (ONLINE = ON);

```

### 10. **`MAXDOP` (SQL Server)**

- Позволяет контролировать максимальное количество процессоров (CPU), которые будут задействованы для создания или перестройки индекса.
- Пример:

```sql

CREATE INDEX idx_email ON users (email) WITH (MAXDOP = 2);

```

### 11. **`COLLATE` (PostgreSQL, MySQL, SQL Server)**

- Указывает сортировку (коллацию) для текстовых колонок в индексе, определяя правила сравнения строк.
- Пример (PostgreSQL):

```sql

CREATE INDEX idx_username ON users (username COLLATE "C");

```

### 12. **`BUFFER_POOL` (MySQL)**

- В MySQL с движком InnoDB можно указать использование конкретного пула буферов для хранения индексов.
- Пример:

```sql

ALTER TABLE my_table ADD INDEX idx_name (name) USING BTREE BUFFER_POOL = innodb;

```

### 13. **`DEFERRED` / `IMMEDIATE` (PostgreSQL, при использовании индексов в ограничениях)**

- Определяет, когда будет проверяться условие уникальности для индексов, участвующих в ограничениях — немедленно или после завершения транзакции.
- Пример:

```sql

SET CONSTRAINTS ALL DEFERRED;

```

Эти параметры позволяют настроить индексы более точно для повышения производительности и оптимизации использования ресурсов в зависимости от конкретных задач и данных в базе данных.
