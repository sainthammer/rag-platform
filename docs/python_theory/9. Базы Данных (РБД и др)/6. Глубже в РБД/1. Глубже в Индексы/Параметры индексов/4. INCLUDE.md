
Параметр **`INCLUDE`** в индексе SQL (доступен в таких СУБД, как **PostgreSQL** и **SQL Server**) позволяет добавлять в индекс дополнительные колонки, которые **не участвуют в сортировке или поиске**, но хранятся в индексной структуре для ускорения выполнения запросов. Это позволяет создавать **покрывающие индексы** (covering indexes), когда все данные, необходимые для запроса, находятся непосредственно в индексе, и база данных не должна обращаться к самой таблице.

### Как работает параметр `INCLUDE`:

Обычно индекс содержит только колонки, по которым происходит сортировка или поиск. Эти колонки называются **ключами индекса**. Однако иногда запросам нужны данные из других колонок, которые не используются для фильтрации или сортировки. Включение таких колонок напрямую в ключи индекса может привести к ненужному увеличению размера индекса и замедлению операций вставки и обновления.

Параметр `INCLUDE` решает эту проблему: он добавляет колонки в индекс **только для хранения данных**, но **не для сортировки или поиска**. Эти колонки могут использоваться для выборки данных напрямую из индекса, избегая дополнительного обращения к таблице.

### Пример использования:

Предположим, у вас есть таблица `orders` с такими колонками: `order_id`, `customer_id`, `order_date`, `total_amount`. Вы часто выполняете запросы, которые фильтруют по `customer_id`, но также часто запрашивают `total_amount`.

Если вы создадите индекс только по `customer_id`, запросы могут по-прежнему обращаться к самой таблице для извлечения значений `total_amount`. С помощью параметра `INCLUDE` можно добавить `total_amount` в индекс, чтобы запросы использовали только индекс для выборки всех необходимых данных.

#### Пример индекса с `INCLUDE`:

```SQL

CREATE INDEX idx_customer_id ON orders (customer_id) INCLUDE (total_amount);

```

Теперь запросы, которые выбирают `customer_id` и `total_amount`, смогут полностью выполняться за счёт индекса без обращения к таблице.

### Преимущества параметра `INCLUDE`:

1. **Ускорение запросов**: Покрывающие индексы позволяют базе данных выполнять запросы, не обращаясь к данным таблицы, что значительно снижает количество операций чтения с диска.

2. **Оптимизация размера индекса**: Колонки, добавленные через `INCLUDE`, не являются частью ключа индекса и не участвуют в сортировке. Это уменьшает размер индекса по сравнению с тем, если бы все колонки были добавлены как ключи индекса.

3. **Повышение производительности сложных запросов**: Запросы, которые требуют доступа к нескольким колонкам, могут быть ускорены за счёт индекса с `INCLUDE`, если все необходимые данные находятся в индексе.

### Когда использовать `INCLUDE`:

1. **Покрывающие индексы**: Если ваш запрос выбирает больше колонок, чем включено в обычный индекс, но эти колонки не нужны для сортировки или фильтрации, их можно добавить через `INCLUDE`. Это позволит сделать индекс покрывающим.

2. **Запросы с выборкой без сортировки**: Если вы часто делаете запросы, где нужны данные из нескольких колонок, но сортировка происходит только по одной или нескольким, другие колонки можно добавить через `INCLUDE`.

3. **Чтение данных из индекса без обращения к таблице**: Если запросы регулярно извлекают дополнительные данные, которые можно получить прямо из индекса, это может существенно снизить нагрузку на диск и ускорить выполнение запросов.

### Пример запроса, использующего индекс с `INCLUDE`:

```SQL

SELECT customer_id, total_amount
FROM orders
WHERE customer_id = 12345;

```

В этом запросе база данных использует индекс `idx_customer_id`, чтобы быстро найти строки по `customer_id`, а также сразу же получить значение `total_amount` из индекса, не обращаясь к таблице.

### Разница между ключами индекса и колонками с `INCLUDE`:

- **Ключи индекса**: Это колонки, по которым происходит сортировка и поиск. Их порядок влияет на производительность запросов, которые выполняют фильтрацию или сортировку по этим колонкам.
- **INCLUDE колонки**: Это колонки, которые добавлены в индекс исключительно для выборки данных и не участвуют в сортировке или фильтрации. Они просто хранятся в структуре индекса для ускорения выборки данных.

### Пример комбинированного индекса:

Допустим, у вас есть запрос, который часто сортирует по `order_date`, но также выводит `total_amount` и `customer_id`. Вы можете создать комбинированный индекс, который будет эффективно обрабатывать такие запросы:

```SQL

CREATE INDEX idx_order_date ON orders (order_date) INCLUDE (customer_id, total_amount);

```

Теперь запросы, сортирующие по дате заказа и запрашивающие `customer_id` и `total_amount`, будут использовать этот индекс без обращения к таблице.

### Пример с сортировкой:

Запрос:

```SQL

SELECT customer_id, total_amount
FROM orders
WHERE order_date > '2023-01-01'
ORDER BY order_date;

```

Этот запрос может быть полностью выполнен с использованием индекса `idx_order_date`, так как он содержит все нужные колонки и удовлетворяет условиям сортировки и фильтрации.

### Особенности и ограничения:

1. **Не все колонки могут быть включены через `INCLUDE`**: В PostgreSQL, например, нельзя использовать `INCLUDE` для выражений (функций), нужно индексировать их как ключи.

2. **Увеличение размера индекса**: Хотя `INCLUDE` помогает сэкономить место по сравнению с добавлением всех колонок в ключи индекса, всё же добавленные колонки увеличивают общий размер индекса.

3. **Поддержка в разных СУБД**: Параметр `INCLUDE` поддерживается не всеми базами данных. Например, он доступен в PostgreSQL и SQL Server, но не в MySQL.

### Заключение:

**`INCLUDE`** — это полезный параметр индексов в SQL, который позволяет добавлять колонки в индекс для ускорения выполнения запросов, не влияя на сортировку или фильтрацию. Это позволяет создавать покрывающие индексы, которые содержат все необходимые данные для запроса, тем самым уменьшая количество обращений к таблице и улучшая производительность запросов.
