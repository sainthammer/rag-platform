
Параметр **`CONCURRENTLY`** используется в **PostgreSQL** и позволяет создавать или перестраивать индексы параллельно с выполнением операций чтения и записи в таблице, к которой применяется индекс. Это особенно полезно для больших таблиц, когда нужно минимизировать время блокировки и избежать прерывания работы приложений.

### Как работает `CONCURRENTLY`:

Когда индекс создается **без** использования `CONCURRENTLY`, таблица блокируется, и любые операции записи (вставки, обновления, удаления) в таблицу приостанавливаются до тех пор, пока процесс создания индекса не завершится. Это может негативно сказаться на производительности, особенно для высоконагруженных систем.

**`CONCURRENTLY`** позволяет создавать индекс в несколько этапов, при этом позволяя продолжать операции чтения и записи в таблицу. Процесс происходит следующим образом:

1. **Первый этап**: Создаются «снимки» данных из таблицы без блокировки записи. Это позволяет собирать начальные данные для индекса.

2. **Второй этап**: Постепенное добавление новых изменений (вставок, обновлений) в создаваемый индекс по мере их поступления.

3. **Третий этап**: Синхронизация индекса с новыми данными, которые были добавлены в таблицу во время его создания. Только на этом этапе возможна короткая блокировка для финализации процесса, но она длится гораздо меньше по сравнению с обычным созданием индекса.

### Пример использования:

```sql

CREATE INDEX CONCURRENTLY idx_users_email ON users (email);

```

В этом примере создается индекс по столбцу `email` таблицы `users`, и процесс выполняется параллельно с продолжающимися операциями в таблице, не блокируя вставки или обновления данных.

### Важные моменты:

1. **Требует больше ресурсов**: Создание индекса с `CONCURRENTLY` требует больше ресурсов, так как процесс должен отслеживать изменения данных и выполнять дополнительные шаги по синхронизации.
    
2. **Медленнее, чем обычное создание индекса**: Из-за необходимости работы с изменениями во время создания индекса, процесс может занять больше времени по сравнению с обычным созданием индекса без `CONCURRENTLY`.
    
3. **Ограничение на транзакции**: Индексы с `CONCURRENTLY` нельзя создавать внутри транзакции. Если попытаться выполнить команду внутри транзакции, PostgreSQL вернёт ошибку:

```sql

ERROR: CREATE INDEX CONCURRENTLY cannot run inside a transaction block

```

4. **Удаление индексов**: Параметр `CONCURRENTLY` также может использоваться для удаления индексов, чтобы избежать блокировок при операциях на таблице:

```sql

DROP INDEX CONCURRENTLY idx_users_email;

```

### Когда использовать `CONCURRENTLY`:

- Используйте **`CONCURRENTLY`**, когда таблица большая и активно используется (особенно для записей), и вам нужно минимизировать влияние на производительность приложения.
- Он полезен для баз данных, которые обслуживают большое количество запросов на запись, где даже короткая блокировка может вызвать задержки или повлиять на работоспособность системы.

### Недостатки:

1. **Низкая производительность при больших нагрузках**: Процесс создания индекса с `CONCURRENTLY` более ресурсоёмкий, и для очень загруженных систем это может снизить общую производительность.
2. **Не подходит для небольших таблиц**: Для маленьких таблиц создание индексов обычно занимает немного времени, и использование `CONCURRENTLY` может быть излишним и замедлит процесс без явных преимуществ.

### Заключение:

**`CONCURRENTLY`** — это полезный параметр в PostgreSQL, который позволяет создавать или удалять индексы без блокировки таблиц для операций записи. Это уменьшает влияние на производительность базы данных, но может занять больше времени и требует дополнительных ресурсов. Использовать его следует в высоконагруженных системах, где критично минимизировать время блокировок при работе с большими таблицами.
