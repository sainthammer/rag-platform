

> [!NOTE] Дополнение от себя после реального опыта работы с ORM SQLAlchemy и Raw SQL
> При масштабировании приложения ваши запросы становятся все сложнее и более интенсивны (миллионы запросов в день, если вы пишете реально нужный кому-то сервис) и от ORM в целях оптимизации вы будете отказываться, так как разультатов выполнения запросов через ORM являются ОБЪЕКТЫ Python, а для Raw SQL это будет кортеж (tuple) - соответственно RAW SQL уже менее затратен по памяти вашего приложения. 
> Но так же само выполнение запросов быстрее, когда вы используете "сырые запросы", так как ORM не нужно их конвертировать в SQL из Python
> В очень больших и производительных приложения доля Raw SQL уже около 80%


Для простых CRUD-операций ORM вполне может сэкономить время разработки и улучшить читабельность кода. Но иногда удобнее пользоваться нативным SQL. Например, сложные выборки/обновления (особенно, аналитические отчеты с оконными функциями и рекурсивными CTE). Компромиссным вариантом является маппинг результатов нативных запросов на объекты, Доктрина это позволяет.

Короче говоря, ORM - спорная вещь, но все же её используют, так как есть ряд **преимуществ:**

1. Помогают абстрагировать базовый домен данных в контексте приложения.
2. Позволяют быстрее работать над основной бизнес-логикой, не отвлекаясь на нюансы хранения данных.
3. Убирают много шаблонного кода, необходимого для взаимодействия с базами данных.
4. Часто включают инструменты миграции, которые помогают управлять изменениями в схеме базы данных на основе изменений в коде.
5. Ускоряет разработку - устраняет необходимость в повторяющемся SQL-коде.
6. Сокращает время разработки.
7. Снижает затраты на разработку.
8. Устраняет различия в SQL для конкретного поставщика - ORM знает, как написать SQL для конкретного поставщика, так что вам не придется этого делать.
9. лучшая структура и организованность
10. лучшее соответствие языку

**Недостатки:**

1. Снижение производительности разработчиков при обучении программированию с помощью ORM.
2. Разработчики теряют понимание того, что на самом деле делает код - разработчик больше контролирует ситуацию, используя SQL.
3. ORM имеет тенденцию быть медленным.
4. ORM не может конкурировать с SQL-запросами при выполнении сложных запросов.
