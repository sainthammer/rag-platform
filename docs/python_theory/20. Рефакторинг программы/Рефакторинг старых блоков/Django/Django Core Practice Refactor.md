# Практика

## Общая суть проекта

Вы пишите небольшую платформу на Django для того, чтобы тестировать Tesseract. По большей части ваш Django сейчас служит своеобразным Front END приложением, у которого есть своя БД, чтобы хранить некоторые данные про картинки и сами картинки от пользователей. А сами анализы картинок будет делать уже написанный вами Fast API микросервис. У пользователей будет возможность добавлять картинки для тестов. Вы будете выводить их на экран главной страницы.

### Практика по Django

#### Задание 1. Модели для БД.

- Кратко:

Пропишите модели используя Django ORM. Сделайте миграции для этих таблиц и накатите их на БД в PostgreSQL

- Подробно:

Используя Django ORM сделайте связку с PostgreSQL. Вот какие таблицы должны быть у вас в БД. Вы можете добавить что-то своё, если хотите.

1. Таблица **docs** с полями: id, file_path, size    

В  этой таблице:

file_path - строка, содержит путь к файлу для Django приложения, файл предварительно загружен в нужную папку, например media
size - размер файла в Кб, в будущем будем делать по нему выборки

2. Таблица **users_to_docs** с полями: id, username, docs_id

В  этой таблице:

username - имя пользователя
docs_id - FK на таблицу docs при загрузке нового файла, будет делаться такая запись.

3. Таблица **price** с полями: id, file_type, price

В  этой таблице:

file_type - расширение файлов, которые наш сервис умеет распознавать (анализировать)
price - float, цена анализ 1 Кб данных, будем в будущем считать цену за анализ файла.

4. Есть таблица **cart** (корзина пользователя) с полями id user_id docs_id order_price payment

В  этой таблице:

user_id - FK на встроенную в Django таблицу user'ов, если писали свою систему аутентификации, то тогда на вашу таблицу пользователей. на id пользователя
docs_id - FK на таблицу docs
order_price - float цена заказа, высчитывается при добавлении файла на основании его типа, размера и цены в таблице price
payment - булева отметка о оплате. Сервиса оплаты у нас не будет, но номинаьно мы просто будем менять статус с по умолчанию при создании заказа с False на True.
