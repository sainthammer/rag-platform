# Практика

Вся работа ведется с помощью SqlAlchemy в python.
Рекомендованный материал - [курс видео по SQLAlchemy](https://www.youtube.com/playlist?list=PLeLN0qH0-mCXARD_K-USF2wHctxzEVp40) (он немного устарел, но это довольно полный курс, просто некоторые строки кода используют устаревший синтаксис, возможно придется погуглить, как некоторые штуки надо делать в новых версиях SqlAlchemy)

1. Начините изучение со [статьи](https://habr.com/ru/articles/848592/) или курс видео выше.
2. Создайте новую бд . Напишите коннектор для подключения к базе данных postgresql. (Очень желательно сделать всю работу с БД асинхронной).
3. Создайте Классы моделей, которые будут реализовывать схему данных на прикрепленном рисунке.
4. Заполните ĸаждую таблицу минимум 5 строĸами данных.
5. Получите данные из таблицы и выведите на экран. Надо сделать пару SELECT запросов, пока что без фильтраций. Просто вывести данные.
6. Сделайте несколько SELECT запросов с JOIN'ами  и выведите на экран результат.
7. Сделайте обновление данных, удаление данных, добавление данных в разных таблицах. (по 3-5 запросов). Обратите внимание, как влияют связи между таблицами на удаление данных.
8. Получите данные фильтрацией WHERE, с сортировкой ORDER BY, группировкой GROUP BY, удалением дубликатов DISTINCT и выведите на экран.
9. Примените несколько функций агрегации и выведите результат на экран.
10. Удалите несколько строк из таблицы Поставщик и выведите на экран строки этой таблицы
11. Настройте Alembic (специальная программа для миграций через ORM в Python). Как это делать можно посмотреть в [ролике](https://www.youtube.com/watch?v=SD6_EPg0Aqk&list=PLeLN0qH0-mCXARD_K-USF2wHctxzEVp40&index=13&t=26s) или почитать [статью](https://habr.com/ru/companies/amvera/articles/849836/)
12. Сделайте первую миграцию миграцию. Затем измените структуру БД (добавьте какую-нибудь новую таблицу в БД), сделайте миграцию. Накатите миграцию на БД. Проверьте, что все применяется через PGAdmin или DBeaver. Теперь откатитесь к прошлой миграции. Проверьте. что все работает.

### Дополнительно

1. Сделайте заполнение какой-нибудь из таблиц хотя бы на 10 000+ строк. Можно написать скрипт, который будет в цикле вставлять записи с рандомной генерацией.
2. Сделайте запрос в такой таблице. Сделайте профилирование времени выполнения запроса.
3. Сделайте создание индексов средствами ORM для таблицы с вот этим большим объемом данных. Теперь сделайте профилирование. Результат изменился? Насколько? Если разница не особо заметна, можно добавить ещё данных (на самом деле 10 000 строк это вообще не о чем, в нормальных БД МИЛЛИОНЫ СТРОК, поэтому Индексы там просто жизненная необходимость).
4. Покройте тестами ваши CRUD операции в SQLAlchemy. Подумайте, как можно сделать тест функции на изменение записи, если нет теста для получения записи? А как протестировать метод на чтение записи из БД? (надо сначала тестировать READ запрос через raw SQL, потом можно говорить что-то о правильности CREATE, UPDATE и DELETE запросов проверяя результаты через READ)
5. Если вы сделали синхронный код для SQL Alchemy CRUD операций и Alembic, то теперь надо сделать все асинхронно.
